## Surprises / side findings

- **Angular `NgFlowService.getNodesBounds` passes no `nodeLookup`** (`ng-flow.service.ts:859-861`, `getNodesBoundsSystem(nodes, { nodeOrigin })`). React's `useReactFlow().getNodesBounds` passes `{ nodeLookup, nodeOrigin }`. So for sub-flow child nodes angular computes bounds from **relative** positions (wrong), and the agent-bridge `get_nodes_bounds` tool (`agent-bridge.service.ts:781-785`) inherits that. The system's "please pass nodeLookup" `console.warn` is gated on `isDevEnv()` (process.env.NODE_ENV), which Angular builds never define, so it never surfaces. Fixing this makes #5871 live, so do both. (Not an upstream changelog item; out-of-scope bug.)
- Dark-mode background colours (#5839) are **duplicated** in angular's `ng-flow.css`, which is appended after the system CSS, so a system-only port would have no visible effect.
- `touch-action` (#5638) and `autoPanOnSelection` (#5677) landed in angflow independently (angular CSS / angular Pane + XYPanZoom divergence), not through the system package.
- Several angflow "DELIBERATE DIVERGENCE" blocks (XYPanZoom selection teardown, `setDevWarnSink`, the middle-click `!userSelectionActive` guard) collide with upstream follow-ups: #6054's `on('zoom', null)`, #5793's `createDevWarn`, #5902. Port the intent, not the diff.
- `ngDevWarn` prints `[angflow]` but links to `https://reactflow.dev/error#<id>`.
- Angular has no `handleType` / `handleId` filtering on `selectNodeConnections`, a feature gap vs React `useNodeConnections` (relevant to #5791).

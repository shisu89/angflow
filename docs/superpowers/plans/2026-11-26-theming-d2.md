# Upstream 1.0 theming alignment — Implementation Plan (sub-project D2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt upstream's 1.0 theming model the way upstream did it. After D2:
- **colour mode:** `colorMode` is removed, and `forceColorMode?: 'light' | 'dark'` replaces it. By default the flow follows the system or page colour scheme through CSS `color-scheme` and `light-dark()` tokens, with no JavaScript (#5843 ef4423b0b, #6118 626f32697);
- **cascade:** every stylesheet angflow ships lives in `@layer xyflow` (#5844);
- **theme file:** `@angflow/angular/xy-theme.css` ships;
- **known failures:** the last two (`props.spec` colorMode) are fixed, and `known-failures.ng.ts` has no entries.

**Release:** the single final release is unchanged: system 0.2.0, angular 0.4.0, mcp 0.1.0, already bumped in D1 and unpublished. D2 adds changelog entries under those headings. The mcp catalog is untouched: no tool reads or sets the colour mode.

**Architecture:**
- **System CSS** becomes byte-identical to `upstream/main`, ported one upstream commit at a time. The only exception is angflow's deliberate `transform-origin: 0 0` on `.xy-flow__viewport-portal` (7f85b06a0).
- **Angular colour mode** becomes a pure class binding.
- **The CSS bundle** is built with postcss (`postcss-import` with `layer()`, `postcss-nested`, `autoprefixer`), the same parser and plugins upstream uses, behind the existing `node scripts/bundle-css.js` entry point.
- **`ng-flow.css`** shrinks to Angular-only rules, inside the layer, with system tokens authoritative.

**Spec:** `docs/superpowers/specs/2026-11-26-theming-d2-design.md`. It is the contract.

**BASE:** `42b15702c` (`docs: D2 theming alignment design …`). D1 (`096c5ed08..12f701b37`) is on `main`, pushed, and CI is green.
